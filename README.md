# 脖动圈 · 微信小游戏

> **用你的头开飞船。** 一款让玩家主动活动颈椎的微信小游戏——摄像头实时追踪头部姿态，
> 转头即转向，娱乐本身就是锻炼。

---

## 这是什么

「脖动圈」把**颈椎活动**做成核心玩法，而不是包装成一个免责声明。

- **核心约束**：必须头部控制（不能退化为陀螺仪或触屏）—— 这是产品的全部创新点
- **形态**：竖屏纵轴卷轴飞行。飞船在屏幕下方，世界迎面涌来，玩家用转头决定飞向哪
- **差异化**：市面上的"体感游戏"多数只用手机陀螺仪；本作用**摄像头人脸姿态追踪**，
  玩家的颈椎必须真的动起来才有输入

## 技术要点

### 姿态追踪链路（iOS 微信小游戏，实测跑通）

```
wx.createCamera({ devicePosition: 'front' })
  → 等 SETTLE_MS(3s) 让前置摄像头真正生效
  → wx.createWorker('workers/index.js', { useExperimentalWorker: true })
  → camera.listenFrameChange(worker)        // iOS 主线程拿不到帧，必须走 Worker
  → worker.getCameraFrameData()             // 返回裸 ArrayBuffer，RGBA 288×512 = 589824B
  → wx.createVKSession({ track: { face: { mode: 2 } } })
  → session.detectFace({ frameBuffer, width: 288, height: 512, sourceType: 0 })
  → 结果只从 updateAnchors 事件回调拿；anchor.angle = (pitch, yaw, roll)，单位是弧度
```

### 踩过的坑（都已固化在文档里）

| 坑 | 真相 |
|---|---|
| `track.face.mode: 1`（摄像头实时）在 iOS 上零事件 | 已判死，只能用 `mode: 2` + `detectFace()` |
| `Camera.onCameraFrame` 在 iOS 主线程拿不到帧 | 必须 `useExperimentalWorker` + `Worker.getCameraFrameData()` |
| 摄像头默认后置启动 | `devicePosition: 'front'` 要约 1s 才生效，取帧前必须等 |
| `wx.createOffscreenCanvas` 在小游戏里不存在 | 那是小程序 API |
| 「推送式洪水」取帧 = 假实时 | 改为**拉取式闭环**（主线程要一帧，worker 才给一帧） |
| 帧搬运慢到 3/s | 桥接带宽实测 `回 ≈ 13ms + 字节/1536`（约 1.5 MB/s），慢在**跨线程序列化**而非拷贝 |
| 自己埋的限速 `PACE_MIN = 80` | 把闭环顶死在 12.5/s。拉取式本就串行，这个下限是多余的 |

### 实测能力（iPhone 16 / 微信 8.0.78 / SDK 3.17.3）

| 降采样档 | 分辨率 | 搬运体积 | 搬运耗时 | 取帧率 | 人脸检出 |
|---|---|---|---|---|---|
| 关 | 288×512 | 589824B | 397~442ms | 2~3/s | 17~22 |
| ÷2 | 144×256 | 147456B | 113~126ms | 8~9/s | 79~94 |
| **÷3（默认）** | **96×170** | **65280B** | **54~93ms** | **17/s** | 162~182 |
| ÷4 | 72×128 | 36864B | 37ms | 21/s | 173/173 |

`detectFace()` 本身只要 **6~7ms**（上限约 39/s）——**瓶颈从来不是算法，是帧搬运**。

## 运行

1. 用**微信开发者工具 Nightly** 打开 `eyegame-wxgame/`（或 `vk-poc/`）
2. AppID 填自己的小游戏 AppID
3. **VisionKit 相关能力模拟器不支持，必须真机预览**

## 设计要点

速度感与可玩性的**解耦**（纵轴玩法的核心取舍）：

```
可反应预算 = 检测60ms + 决策250ms + 横移208ms + 余量80ms = 600ms
→ 机制层速度上限 1.30 H/s（加顶部预告区 1.55）
→ 但速度感需要视觉流动 3~9 H/s
→ 视觉速度自由拉高（不参与碰撞），机制速度被红线压住
```

还有：

- **泳道防挫败**：横向 5 泳道，每波至少留 1 条完全空泳道，永远存在通路
- **Boost 是短促动作**：抬头 ≤3s + 冷却 4s。若做成"保持角度=保持速度"，会让人长时间维持一个颈椎角度，与产品定位冲突
- **颈椎安全做成机制**：左右平衡计分、禁甩头、单局封顶、转幅分级

## 隐私与合规

- **全程仅本机实时处理，人脸数据不落盘、不上传**
- 小游戏需在 MP 后台《用户隐私保护指引》中声明「访问你的摄像头」（未声明会报 `1026 隐私接口被封禁`）
- 商业化：纯免费。**无版号不可接付费**（硬边界）
- 版号、软著、实名防沉迷由持证出版单位与法务办理；政策以国家新闻出版署与微信开放社区最新口径为准
