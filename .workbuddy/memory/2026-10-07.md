## 三个关键设计判断

### 1. 形态前提（读代码后确认）
- 纵轴游玩**必须竖屏**：主工程现为 `landscape`，改 `game.json` 一行 `deviceOrientation:"portrait"`
- 渲染栈是 **Canvas 2D**（`wx.createCanvas()`，非 WebGL）→ 速度感走 **伪 3D 投影**
  （物体带 x,z；屏幕位置=投影(z)，尺寸∝1/z）+ 多层视差，2D 完全够用
- 主工程当前跑的仍是 `onAccelerometerChange` **陀螺仪版**（即"定位塌了"那版）→ 切片要把
  POC 的 VisionKit 管线替换进来，但保留陀螺仪作降级兜底

### 2. ★ 速度感与可玩性必须解耦（本规格核心论证）
- **可反应时间预算**：检测 60ms + 决策 250ms + 横移到位 208ms + 余量 80ms = **600ms**
- 推出机制层速度上限：`V_mech ≤ 0.78H / 0.600s` = **1.30 H/s**；加顶部 15% 预告区后放宽到 **1.55 H/s**
- 但"速度感"需要视觉流动 **3~6 H/s**（甚至 Boost 时 9 H/s）→ 中间差 **2.5~4.5 倍**
- **结论：视觉速度自由拉高，机制速度被红线压住。爽感靠视觉层（不参与碰撞），可玩性靠机制层守。**
- Boost 刻意只把机制速度从 1.30 提到 1.45，却把视觉速度从 6 拉到 9 —— 卖的是"我在狂冲"的体感

### 3. pitch 改做 Boost（抬头氮气）
- 纵轴下"屏幕上下位移"这个自由度消失 → pitch 自然从"垂直移动"转成**油门**
- 做成「抬头 ≤3s + 冷却 4s」的**短促动作**：恰好是颈椎需要的间歇大幅活动，
  且不会长时间保持仰头。**若做成"保持角度=保持速度"会与颈椎定位直接冲突。**

## 其他要点
- 飞船位置：屏幕中心 → **y=0.78H**（前方留白 = 视野 = 向前看 → 代入感）
- **泳道模型防挫败**：横向 5 泳道，每波**至少留 1 条完全空泳道**，保证永远存在一条可通行路径
- **纵向间距下限 0.22H**（由可反应距离推出；低于此值人类无法稳定通过）
- 速度感六手法（按性价比）：① 近景速度线(视差4~6) ② 引擎尾迹 ③ 星场三层视差 ④ FOV 收缩
  ⑤ 运动模糊 ⑥ 引擎音高。粒子总量 ≤150（Canvas 2D 全屏重绘安全线）
- 60s 节奏：校准 8s / 巡航教学 10s / 双向穿行 14s / 提速 6s / Boost 段 12s / 冲刺 8s / 收尾 2s
- 颈椎安全强化：Boost 限次（≤3s+冷却）、左右平衡计分、禁甩头、90s 封顶

## 🔴 技术前置风险（下一步必须先验）
**Camera 原生组件遮挡**：小游戏 `wx.createCamera` 创建的是**原生组件**，会占屏幕区域。
正式游戏**绝不能显示摄像头预览**（破坏代入感 + 用户不适）。必须验证：
> 能否把 Camera 位置/尺寸设到屏幕外或 1px，且**不影响 `getCameraFrameData()` 取帧**？

若不能 → 备选方案：把预览叙事化成"飞船的后视镜 / 传感器窗口"（限制转成设计）。
**这是切片能否成立的地基，验不过就没有沉浸式纵轴。**

## 姿态源抽象（必须有降级路径）
```
PoseSource 接口
 ├── VisionKitSource  主路径（iOS，已实测通过）
 ├── GyroSource       兜底（Android / 检测失败）
 └── MockSource       开发期调试，无需真机
```
统一输出 `{yaw, pitch, roll, confidence, faceFound, ts}`（弧度）。
用陀螺仪时**关闭 Boost**（陀螺仪 pitch 不可靠），并提示"精度降低"。

# 同日续 2：MVP v2 —— 转向方向修正 + 玩法换「穿越隧道」

## 用户决策（两项）
Eric：「修正一下，脑袋转动的方向和飞机运动的方向要一致，挑战换成穿越隧道而不是躲障碍物」

## 修正 1：转向方向（真 bug，根因是符号）
- **POC 实测：左转头 → yaw 增大、右转头 → yaw 减小**（v13 已记录）
- 但投影是 `sx = cx + wx*PPX/z` → **wx 越大越靠右**
- 所以原实现：左转 → yaw↑ → wx↑ → **飞船右移** ❌ 与直觉相反
- **修法**：`CFG.YAW_SIGN = -1`，控制器入口 `raw = (p.yaw - p.nYaw) * YAW_SIGN`
  → 方向约定全部收口到一个常量，真机若仍反只改这一个数
- ⚠️ **连带修正：`trackNeck()` 的左右也标反了** —— 原代码把 `yaw > 阈值` 记成「右转」，
  而实测那是**左转**。不改则结算页左右平衡率整体颠倒（而平衡率正是产品核心卖点）。
  已改为 `y > th → left++`，冒烟新增 H2 守这条。
- **教训**：坐标系的符号约定必须写进代码注释。原文档只写了「左转↗右转↘」（指曲线方向），
  没写「屏幕 x 与 wx 的关系」，于是量产时把两件事当成同一件事。

## 修正 2：玩法换「穿越隧道」（不是换皮，是换对了机制）
| 维度 | 躲障碍（旧） | 穿越隧道（新） |
|---|---|---|
| 操作类型 | 离散躲避（要瞬间精确） | **连续追踪**（渐进跟随） |
| 与 17~21/s + 44~58ms 延迟 | ❌ 做不了瞬间精确 | ✅ 正好落在能力区间 |
| 颈椎动作 | 急促甩头 | **平滑连续摆动**（正是舒缓目标） |
| 与速度感兼容 | 障碍太快=不可玩 | **视觉可更疯，机制仍受红线约束** |

→ **把技术限制变成了设计优势**：躲障碍必须压速度到"反应得过来"，所以速度感上不去；
隧道只需约束**中心线曲率**，世界推进速度可单独拉高 —— 视觉爽感与可玩性第一次真正解耦。

### 机制与参数
- 中心线用**控制点链** `pts=[{zt,cx,hw}]`（zt=世界坐标，飞船固定在 `zt=scroll+SHIP_Z`）
  每帧裁剪身后/补足身前 → 控制点数恒定 ~22，**内存零增长**
- 判定：`|wx − cx| > hw − SHIP_HW` → 蹭壁扣血；蹭壁**软推回 45%**（非硬传送）+ 1200ms 无敌期
- 计分：存活分 + **居中加成**（`cent·14·dt`）→ 逼玩家「稳住中线」而非猛冲（D8：9.25 vs 4.35）
- 参数：`TUN_HW_MAX 0.66 → TUN_HW_MIN 0.42`（难度收窄）· `TUN_HH 1.10`（纯视觉）
  · `TUN_SLOPE_MIN/MAX 0.12/0.28`（中心线斜率上限）· `TUN_STEP 4.0`
  · `TUN_X_LIMIT 0.85` · **`X_LIMIT 1.05 → 1.25`**（0.85+0.42≈1.27，对齐后才不用够不到管外半边）
- ★ **可玩性红线**：`|Δcx| ≤ slope × TUN_STEP` 强制约束 → 中心线只做"有惯性的平滑摆动"
  **量化校验（冒烟 E7）**：最难档变化率 0.28×20 = **5.6/s** vs 飞船横移能力 **35/s** → 余量 6.2 倍
- 渲染：对数采样 21 档 → **左右管壁连续折线**（7px 半透明辉光 + 2px 亮线）+ **横向肋条**
  （alpha 随 zn² 渐亮、线宽渐粗 = 速度感主力）；受击转红、Boost 转金

# 同日续 3：MVP v3 —— 主控轴改「歪头（roll）」

## 用户决策
Eric：「通过头在平面上左右扇形运动来控制飞船，就是脑袋向左右肩歪这个动作，这个动作对脖子来说更舒服」
→ 横向主控量从 **yaw（转头）** 换成 **roll（向左右肩歪）**。用户理由成立：
   转头动用颈旋转肌群（持续单侧易累）；歪头是颈侧屈（幅度小、前庭刺激弱、更放松）。

## ⚠️ 硬代价：roll 噪声是 yaw 的 3~5 倍（POC 实测）
- yaw/pitch σ ≈ 0.013~0.026 rad（<1.5°）· **roll σ ≈ 0.074 rad（≈4.2°）**
- **这正是上一版把 roll 定为"仅装饰"的原因** → 要它做主控，滤波必须整体做厚一档，
  且**两轴参数必须分开写**（一套参数不可能同时合适）。
- 新 roll 档：死区 3°→**4°** · EMA τ 0.09→**0.20s** · 外推 0.55→**0.40**

## 符号约定（统一）：`轴值 > 0 ⟺ 飞船向右移`
- yaw：POC 实测左转 yaw 增大 → `YAW_SIGN=-1`（已实证）
- roll：**方向至今未实测** → `ROLL_SIGN=-1` 是先验猜测
- 真机若反：① 点「控制」切「歪头·位置反」档 ② 翻 `CFG.ROLL_SIGN` 一个常量
- HUD 左下显示 `歪头±X.XX`（**带符号**）→ 念这个数就能一次定死符号

## 四种控制档（「控制」按钮循环）
`歪头·位置`(默认) → `歪头·位置反` → `歪头·速度` → `转头·位置`(回退)，存 `bd_ctrl`
- 默认位置律理由：隧道是"跟中心线"，位置律=照抄隧道形状歪头，不需预判；
  速度律要预测弯道+反配平，叠加 44~58ms 延迟会很难。
- 速度律的好处：回正即停，**不需要维持歪头角度**（与 pitch Boost 同一条原则）

## 顺带修掉
1. **丢脸兜底**（新）：>400ms 无脸 → 输入回中（旧版会带最后一帧一路跑偏）
2. **零点慢速校正**（新）：仅静息带内 τ≈10s 跟随。带内输出本就是 0，改了不影响操作，
   只吃 VisionKit 慢漂移（该轴做主控后漂移会表现为"船自己慢慢跑"）
3. **陀螺仪源重映射**：手机侧倾从喂 pitch 改为喂 roll；并按规格**陀螺仪下关闭 Boost**
4. **颈椎记账跟随主控轴**，且**左右与舵向同向**（上一版踩过标反：平衡率是核心卖点）
5. HUD：`转头 N`→中性 `脖动 N`；调试行显示当前轴 + 带符号读数
6. 底部**三按钮**：控制 / 输入源 / 相机
7. 机身压倾改为与舵向**同号**（往哪边转往哪边压）

## 落地

### P0 能量块 —— 本版存在的理由
- 块的横向 = `中心线cx + off×半宽hw`（跟着隧道走，**只有 off 是额外的颈部横摆量**）
- 生成单位 = **pattern（串）**：sweepR/L · wave · zig · edgeR/L · near（共 7 种，带难度权重）
- ★ **居中加成 14 → 5（`ROOM_SCORE`）**：不降的话玩家最优解仍是贴中线、无视块，P0 直接落空
  收益结构：能量块 ≈1350 vs 居中 ≈300（4.5×）
- ★ **节拍按时间不按距离**（`ORB_GAP_SEC=0.52s`）。0.52s 由来：视野纵深 34 / 速度 9.6 ≈ 3.5s，
  一串 4 块 = 2.1s → 视野内 1.8 串（旧值 1.05 时一串就占满视野，屏幕上只有孤零零一个块）
- ★★ **`gapScale` 跨度越大节拍越长**（zig 1.56×hw→1.5×、wave 1.0→1.3×、sweep 0.16→1.0×）
  —— 缺了它 zigzag 一个节拍内物理上走不完。这是「可玩性红线」在能量块上的形式
- 碰撞用**跨越飞船平面**（`pz>0 && dz<=0`）而非窗口判定：高速一帧走 0.46 单位，窗口式必漏
- 连击：**错过不清零，只有蹭壁清零**（主动放弃收益换安全不该被惩罚）；倍率封顶 9
