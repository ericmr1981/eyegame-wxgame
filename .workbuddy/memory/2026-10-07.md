## 三个关键设计判断

### 1. 形态前提（读代码后确认）
- 纵轴游玩**必须竖屏**：主工程现为 `landscape`，改 `game.json` 一行 `deviceOrientation:"portrait"`
- 渲染栈是 **Canvas 2D**（`wx.createCanvas()`，非 WebGL）→ 速度感走 **伪 3D 投影**
  （物体带 x,z；屏幕位置=投影(z)，尺寸∝1/z）+ 多层视差，2D 完全够用
- 主工程当前跑的仍是 `onAccelerometerChange` **陀螺仪版**（即"定位塌了"那版）→ 切片要把
  POC 的 VisionKit 管线替换进来，但保留陀螺仪作降级兜底

### 2. ★ 速度感与可玩性必须解耦（本规格核心论证）
- **可反应时间预算**：检测 60ms + 决策 250ms + 横移到位 208ms + 余量 80ms = **600ms**
- 推出机制层速度上限：`V_mech ≤ 0.78H / 0.600s` = **1.30 H/s**；加顶部 15% 预告区后放宽到 **1.55 H/s**
- 但"速度感"需要视觉流动 **3~6 H/s**（甚至 Boost 时 9 H/s）→ 中间差 **2.5~4.5 倍**
- **结论：视觉速度自由拉高，机制速度被红线压住。爽感靠视觉层（不参与碰撞），可玩性靠机制层守。**
- Boost 刻意只把机制速度从 1.30 提到 1.45，却把视觉速度从 6 拉到 9 —— 卖的是"我在狂冲"的体感

### 3. pitch 改做 Boost（抬头氮气）
- 纵轴下"屏幕上下位移"这个自由度消失 → pitch 自然从"垂直移动"转成**油门**
- 做成「抬头 ≤3s + 冷却 4s」的**短促动作**：恰好是颈椎需要的间歇大幅活动，
  且不会长时间保持仰头。**若做成"保持角度=保持速度"会与颈椎定位直接冲突。**

## 其他要点
- 飞船位置：屏幕中心 → **y=0.78H**（前方留白 = 视野 = 向前看 → 代入感）
- **泳道模型防挫败**：横向 5 泳道，每波**至少留 1 条完全空泳道**，保证永远存在一条可通行路径
- **纵向间距下限 0.22H**（由可反应距离推出；低于此值人类无法稳定通过）
- 速度感六手法（按性价比）：① 近景速度线(视差4~6) ② 引擎尾迹 ③ 星场三层视差 ④ FOV 收缩
  ⑤ 运动模糊 ⑥ 引擎音高。粒子总量 ≤150（Canvas 2D 全屏重绘安全线）
- 60s 节奏：校准 8s / 巡航教学 10s / 双向穿行 14s / 提速 6s / Boost 段 12s / 冲刺 8s / 收尾 2s
- 颈椎安全强化：Boost 限次（≤3s+冷却）、左右平衡计分、禁甩头、90s 封顶

## 🔴 技术前置风险（下一步必须先验）
**Camera 原生组件遮挡**：小游戏 `wx.createCamera` 创建的是**原生组件**，会占屏幕区域。
正式游戏**绝不能显示摄像头预览**（破坏代入感 + 用户不适）。必须验证：
> 能否把 Camera 位置/尺寸设到屏幕外或 1px，且**不影响 `getCameraFrameData()` 取帧**？

若不能 → 备选方案：把预览叙事化成"飞船的后视镜 / 传感器窗口"（限制转成设计）。
**这是切片能否成立的地基，验不过就没有沉浸式纵轴。**

## 姿态源抽象（必须有降级路径）
```
PoseSource 接口
 ├── VisionKitSource  主路径（iOS，已实测通过）
 ├── GyroSource       兜底（Android / 检测失败）
 └── MockSource       开发期调试，无需真机
```
统一输出 `{yaw, pitch, roll, confidence, faceFound, ts}`（弧度）。
用陀螺仪时**关闭 Boost**（陀螺仪 pitch 不可靠），并提示"精度降低"。

### ★ 最大技术进展：Camera 可以隐藏
`wx.createCamera` **接受 `x / y / width / height`** → 把预览丢到屏幕外（`x:-4,y:-4,w:2,h:2`），
正式游戏画面里**看不到任何摄像头预览**。规格 §11.1 的头号风险解除（待真机确认取帧不受影响）；
若藏起来取不到帧，按钮可切回可见小窗（备选叙事方案也留着）。

### 实现要点
- 竖屏（`game.json` portrait + `workers` 字段）
- 伪 3D 投影：`sy = horizon + PPY/z`，`sx = cx + wx*PPX/z`，尺寸 ∝ 1/z
  （`PPY = 0.56H*SHIP_Z`，`PPX = 0.38W*SHIP_Z`，SHIP_Z = 8）
- 5 泳道防挫败：每波至少留 1 条空泳道，且**与上一波空泳道相邻可达**（keepOpen 取自上波空道±1）
- 控制器：死区 3° + EMA α0.35 + 速率外推 0.55；yaw×2.2 → 世界横向，软限位 ±1.05
- Boost：|pitch|>8° 触发，≤3s + 冷却 4s（**方向未实测**，先用绝对值两侧都能触发）
- 速度感三件套：星场三层视差（0.5/2/5）+ 从中心向外飞出的速度线 + 引擎尾迹（长度∝速度）
- 三档输入源自动降级：`visionkit → gyro → touch`；摄像头 6s 未就绪自动降级（防黑屏）
- 颈椎记账：带滞回的左右转头计数 + 平衡率，结算页展示

### 冒烟抓到的真 bug（值得记）
**`trackNeck` 的滞回写法错误**：旧代码"先判进入、再判退出"，导致**从左直接切到右**时
那一次转身被吞掉（要先退回中立，等下一帧才计数）。改为"**先退出滞回、再重新判定**"。
→ 这是纯逻辑 bug，肉眼看不出来，只有离线断言能抓到。

### 经验（测试侧）
- mock 的 `createCamera` **必须回调 `success`**，否则 `camReady` 永远 false，整条取帧链路测不到
- **小游戏主 canvas 尺寸 = 屏幕逻辑像素**（与触摸 `clientX/clientY` 同坐标系），
  不是物理像素 → mock 用 375×812 而不是 750×1624
- mock 的 worker 排空队列**必须用快照**（`splice(0, len)`）而不是 `while(len)`：
  帧回调会同步触发下一次 `need`，用 while 会永远排不空 → 死循环（超时被 SIGTERM 杀掉）
