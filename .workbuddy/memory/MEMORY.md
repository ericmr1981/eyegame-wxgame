## VisionKit 链路（唯一可用路径）
`wx.createCamera({devicePosition:'front'})` → 等 `SETTLE_MS`(3s) 前置生效
→ `wx.createWorker(...,{useExperimentalWorker:true})` + `listenFrameChange(worker)`
→ worker 内 `getCameraFrameData()` 取裸 ArrayBuffer → 主线程 `createVKSession({track:{face:{mode:2}}})`
+ `detectFace({frameBuffer,w:288,h:512,sourceType:0})` → 结果**只从 `updateAnchors` 事件**
`anchor.angle`=(pitch,yaw,roll) **弧度**；帧 **RGBA 288×512=589824B**（不带宽高）；相机**默认后置**须等 1s
- **✅ Camera 可隐藏**：接受 `x/y/width/height` → 丢屏幕外 `-4,-4,2,2` 无预览
- `wx.createOffscreenCanvas` 小游戏不存在 · `open3d` 需微信 ≥8.1.0（当前 8.0.78 不可用）
- iOS 主线程 `Camera.onCameraFrame` 拿不到帧 · **冒烟**：主 canvas = 屏幕逻辑像素

## 玩法 · 纵轴隧道
规格 `脖动圈_垂直切片设计规格v1.0_纵轴_2026-10-07.md`（含 v1.1 横幅）
最新变更 `脖动圈_MVP_v5_能量块_2026-10-07.md`（v4 幅度档 / v3 歪头主控见同名文档）
- 纵轴卷轴：飞船 y=0.78H，世界从上方涌来 → **必须竖屏**；Canvas 2D + 伪 3D（尺寸∝1/z）
- ★ **速度感与可玩性解耦**：机制速度有红线，视觉速度自由拉高
- **玩法 = 穿越隧道**：须保持管内、贴中心线；`|wx−cx| > hw−SHIP_HW` 扣血；
  蹭壁软推回 45% + 1200ms 无敌 · 红线：中心线斜率 ≤ 0.28
  渲染：对数采样 21 档 → 左右管壁折线 + 横向肋条（肋条渐亮渐粗 = 速度感主力）
- **控制（v4 定稿）**：**歪头 roll → 横移**，约定 `轴值>0⟺右移`，`ROLL_SIGN`/`YAW_SIGN` 一处收口
  · **v4 翻正 `ROLL_SIGN = +1`**（头向右肩歪 → 飞船右移，与头部方向一致）
  · roll 滤波必须比 yaw 厚：EMA τ0.20s、外推 **0.30**（yaw 档 3°/0.09/0.55）
  · **★ v4「幅度」档**（底部第 2 按钮，落盘 `bd_range`）：只改 **dead+full**，
    `ROLL_XRANGE=1.15`/`ROLL_VMAX=5.5` **三档恒定**（不动机动能力，切档不会够不着弯道）
    紧凑 3°/20° · **标准 4°/30°(默认)** · 舒展 5°/40°；颈椎阈值 8°/11.5°/14.9°
  · **★ 降敏感度的正确姿势 = 抬高满量程，不是砍增益**（砍增益只让飞船变肉、脖子照样不多动）
  · 四档控制（「控制」按钮循环）：歪头·位置(默认)/位置反/歪头·速度/转头·位置
  · **pitch→Boost（≤3s+冷却 4s）** · 丢脸>400ms 输入回中 · 零点静息带慢校正(死区×1.3)
- 降级：`visionkit → gyro → touch`（摄像头 6s 未就绪自动降级）

## ★ v5 能量块（P0）· 2026-10-07
**设计要点**：块的横向 = `中心线cx + off×半宽hw` —— 跟着隧道走，**只有 off 是额外的颈部横摆量**。
生成单位是 **pattern（串）**而非单块（sweep/wave/zig/edge/near），逼玩家**连续跟随**。
- ★ **配套硬改动：居中加成 14 → 5（`ROOM_SCORE`）**。否则玩家最优解仍是贴中线、无视块 → P0 落空。
  改后收益结构：能量块 ≈1350 vs 居中 ≈300（4.5×）。冒烟 O16 守。
- ★ **节拍按时间不按距离**（`ORB_GAP_SEC=0.52s`）：速度 9→20，按距离会让节奏快一倍。
  0.52s 的由来：视野纵深 34 单位 / 速度 9.6 ≈ 3.5s，一串 4 块 = 2.1s → 视野内约 1.8 串。
- ★★ **`gapScale`：跨度越大节拍越长**（zig 1.56×hw → 1.5×；sweep 0.16 → 1.0×）。
  缺了它 zigzag 物理上走不完。这是「可玩性红线」在能量块上的形式（同 `TUN_SLOPE_MAX`）。
- 碰撞用**跨越飞船平面**（`pz>0 && dz<=0`）而非窗口判定 —— 高速一帧走 0.46 单位，窗口式必漏。
- 连击：**错过不清零，只有蹭壁清零**（放弃收益换安全不该被惩罚）。倍率封顶 `COMBO_CAP=9`。

## ★ v5 抓到的真 bug：能量块"断流"（空窗 39.5% → 0%）
**根因**：`refillOrbs` 用 `TUN_FWD(64)` 当生成上限，但视野只到 `shipZt+34`。新串生成在视野外
19 单位处 → `updateOrbs` 第一次裁剪就把它们**永久删掉** → scroll 追上时早没了 → 屏幕周期性空窗。
**修法（两道防线）**：① 生成上限贴着视野：`scroll + SHIP_Z + ORB_VIEW(=28)`；
② 裁剪上界放宽到 `ORB_VIEW + 40`，只砍"已被越过"的。顺带 `Z_FAR` 30→36 留预见时间。

### ★ 立项核查结论（2026-10-07，**修正旧记录**）
- **❗ 修正：个人主体「可以」注册微信小游戏**（此前记成"须企业/组织"，错的）。
  官方《小程序备案服务内容指引》「游戏→网络游戏类」标注个人备案可选。
  真正区别是**个人开不了虚拟支付（内购）**、不能投微信广告。纯免费/纯广告 → 个人主体够用。
- **软著是硬门槛**（无论主体、无论是否内购），周期 30~60 工作日。
  ⚠️ **2026-03-15 起新版申请表要求手抄承诺「未使用 AI 开发编写代码/撰写文档/生成申请材料」**，
  配套诚信制度 + 失信入个人征信；转为"有限实质审查"（功能-代码-文档交叉核验）。
  → ★ **本项目代码大部分由 AI 编写，按现状申请软著 = 虚假申报风险**。这是上线的关键路径阻塞项。
  出路：① 让人工贡献成事实主体（重写核心 + 证据链：git 史/实测报告/冒烟）；② 问正规代理机构的实操尺度。
  查证：ccopyright.com.cn（看新版申请表原文）
- **ICP 备案**：2023-09-01 起强制，微信公众平台代提交，通过后才能发布。
- **版号**：纯广告变现不需要；含内购必须（否则开不了虚拟支付）。
- 对外文案红线：**不能宣称"治疗/缓解颈椎病"**（医疗广告范畴）。只能写"活动颈部/放松"。
